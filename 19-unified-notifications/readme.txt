Canonical intelligent attention and notification operating system for the Sabri Social Homeopathy Platform.

== Description ==

File 19 consumes versioned factual events from approved domain owners and creates privacy-minimized notification projections. It does not replace domain state, decisions, messages, appointments, publishing, search/discovery or marketplace truth. Runtime access follows current File 00 membership claims; File 20 owns the single bell/shell placement, File 25 owns shared visual tokens and File 26 owns global search/discovery.

Runtime 3.0.1 preserves the complete 3.0 advanced scope and adds the post-review correctness repairs for partial attention/device state, optimistic device concurrency, health-aware provider routing, privileged routing-cost evidence, strict AI citation rejection, saved-search owner binding, automation input safety, complete paginated advanced privacy export and full core actions after dynamic inbox rendering. Schema remains 3.0.0.

The 3.0 capability set includes smart/explainable priority, Priority Inbox, AI catch-up with deterministic fallback, source-ID citation binding, search/history, snooze, pin, needs-action/done, semantic grouping keys, focus modes, attention budgets, essential-only, temporary mute, best-time scheduling, adaptive frequency caps, live/revocable projections, native-owner actions, verified-source provenance, correction/retraction watch audiences, user automation and saved-search watches, per-device controls, Web Push/FCM/APNs readiness, opt-in WhatsApp/RCS adapters, provider failover, cost-aware routing, simulator/shadow/canary framework, trace explorer, synthetic diagnostics and privacy lifecycle coverage.

AI is optional and does not become domain authority. WhatsApp/RCS, FCM and APNs require separately configured providers and staging acceptance. More notifications are not treated as a KPI.

== Installation ==

1. Install on controlled staging first.
2. Configure encryption/signing material and approved provider adapters outside the repository.
3. Register producer contracts and File 00 identity assertions (`sabri_membership_claims_v2`).
4. Confirm the File 20 single-bell slot and context controls.
5. Run System Check, functional, security, accessibility, provider, backup/restore and rollback acceptance before production.
