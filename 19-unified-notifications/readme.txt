== Description ==

File 19 consumes versioned factual events from approved domain owners and creates privacy-minimized notification projections. It does not replace domain state, decisions, messages, appointments, publishing, search/discovery or marketplace truth. Runtime access follows current File 00 membership claims; File 20 owns the single bell/shell placement, File 25 owns shared visual tokens and File 26 owns global search/discovery. The platform has one complete free tier and donation/payment status does not alter notification access, priority, delivery or visibility.

Runtime 2.4.0 includes the Top-20 notification family CV-097 through CV-106: one unified center, provider-aware channel preferences, person/topic/community/course/event/doctor/channel subscriptions, daily/weekly digest scheduling, appointment reminders, correction/retraction alerts, security alerts, opt-in creator bulletins, truthful delivery evidence and privacy-minimized notification-fatigue signals.

The 2.4.0 corrective cycle also hardens immutable validated event envelopes, bounded payload complexity and metadata, event-bound templates, most-specific policy precedence, File 00 sole positive identity authority, multi-device token ownership, REST intake isolation, expiry handling, click-time deep-link authorization, audit-chain serialization/minimization, complete privacy export pagination, atomic dead-letter retry, provider credential corruption handling, truthful unsubscribe results, 44px accessibility targets and expanded System Check evidence.

== Installation ==

1. Install on controlled staging first.
2. Configure encryption/signing material and provider adapters outside the repository.
3. Register producer contracts and File 00 identity assertions (`sabri_membership_claims_v2`).
4. Confirm the File 20 single-bell slot and context controls.
5. Run System Check, functional, security, accessibility, backup/restore and rollback acceptance before production.
