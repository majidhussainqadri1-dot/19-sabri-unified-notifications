Canonical intelligent attention and notification operating system for the Sabri Social Homeopathy Platform.

== Description ==

File 19 consumes versioned factual events from approved domain owners and creates privacy-minimized notification projections. It does not replace domain state, decisions, messages, appointments, publishing, search/discovery or marketplace truth. Runtime access follows current File 00 canonical membership assertions; fresh privileged step-up comes from File 02; File 20 owns the single bell/shell placement and Safe Mode; File 24 owns cross-cutting assurance/containment; File 25 owns shared visual tokens and File 26 owns global search/discovery and saved-query truth.

Runtime 3.0.4 preserves the complete 2.4 baseline and adds smart/explainable priority, Priority Inbox, AI catch-up with deterministic fallback, source-ID citation binding, search/history, snooze, pin, needs-action/done, semantic grouping keys, focus modes, attention budgets, essential-only, temporary mute, best-time scheduling, adaptive frequency caps, live/revocable projections, native-owner actions, verified-source provenance, correction/retraction watch audiences, user automation and saved-search watches, per-device controls, Web Push/FCM/APNs readiness, opt-in WhatsApp/RCS adapters, provider failover, cost-aware routing, simulator/shadow/canary framework, trace explorer, synthetic diagnostics and privacy lifecycle coverage.

AI is optional and does not become domain authority. WhatsApp/RCS, FCM and APNs require separately configured providers and staging acceptance. More notifications are not treated as a KPI.

== Installation ==

1. Install on controlled staging first.
2. Configure encryption/signing material and approved provider adapters outside the repository.
3. Confirm File 00 `SMC_Contracts::assertions()` and, for privileged step-up actions, File 02 passkey assurance are available.
4. Confirm the File 20 notification surface/Safe Mode contracts, File 24 containment contract and any required producer contracts.
5. Run System Check, functional, security, accessibility, provider, backup/restore and rollback acceptance before production.
